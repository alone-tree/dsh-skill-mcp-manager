# 按会话隔离 MCP 实例

> 状态：已实现并合并入 `docs/DESIGN.zh.md`。本专题不再更新。

## 问题

当前能力库按 MCP 名称在 Host 中复用同一个运行实例。多个 DSH 会话同时调用 Playwright 等有状态 MCP 时，会共享浏览器页面、当前标签页或其他运行态，可能互相覆盖。目标是建立通用的会话隔离机制，不针对某个 MCP 编写特例。

## 已确认并落地的边界

- 同一 MCP 配置在每个 DSH 会话中均创建、持有和销毁独立实例，不为特定 MCP 编写特例。
- stdio MCP 由每个会话各自启动子进程；HTTP MCP 由每个会话各自建立连接。
- 子代理是独立会话，拥有独立 MCP 实例，不与父会话共享。
- 不为 DSH 重启、会话恢复增加额外持久化或恢复逻辑；实例生命周期保持与 DSH 会话运行时一致。
- MCP 配置管理保持全局共享；仅运行实例与调用状态按会话隔离。
- 保持现有三档语义：eager 在每个会话首次 pre-step 时启动该会话实例；on-demand 在该会话首次 `mcp_load` 时启动；disabled 不启动。
- 隔离边界只到会话；同一会话内保留现有工具调用并发语义。
- 管理页删除「已连接」和「断开」；原「加载」改为「刷新快照」：一次性试连、更新 `registry.json`，然后关闭，不留下会话实例。
