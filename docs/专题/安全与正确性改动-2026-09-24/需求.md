# 安全与正确性改动需求

> 状态：已实现（2026-09-24）。行为以 `docs/DESIGN.zh.md` 为准。
>
> 来源是外部审查 [PR #3](https://github.com/alone-tree/dsh-skill-mcp-manager/pull/3) 指出、并已对照当前 `main`（1.1.6）核对过的问题。不采用该分支的代码。重写时可以参考其中边界清楚的做法。
>
> 本文只写现在的行为、要达成的结果、明确不做的事、以及还没定的选择。不写实现。

## 要做

### 1. 本地工具不再自动拿到这台电脑上的密钥

现在每启动一个本地工具，都会把这台电脑环境里的全部变量交给它，包括密钥、口令、令牌，以及 DeepSeek Harness 自己的内部变量。远程地址的工具不走这条路。

要达成：

- 名字像密钥、口令、令牌的变量不交给本地工具。
- DeepSeek Harness 自己的内部变量不交给本地工具。
- 在这个工具上特意填写的值保留，并且盖过上面丢掉的同名项。
- 与系统自带客户端的交接范围对齐：自带客户端不交出去的，这里也不交。

### 2. 配置里的环境变量引用，在启动时换成真值

设计文档已经定过：值可以是明文，也可以是「美元符号加变量名」这种引用，这样密钥不必写进配置文件。现在引用没有被换成真值，工具收到的是那串原文。

要达成：

- 整段都是「美元符号加一个变量名」时，在启动本地工具的那一刻，换成这台电脑环境里的对应值。
- 环境里没有这个名字时，换成空，不把原文交出去。
- 不是这种整段写法的，仍按字面值使用。这一点维持设计文档里的已定口径，避免引用写法本身带来新问题。

### 3. 说明书写的卸载步骤要真的能卸

两份说明都让人在卸插件前运行 `/mcp prepare-uninstall`，把托管配置交还原来的管理方式。这句话现在只是再列一遍服务器。真正做交接的是另一条命令 `/prepare-uninstall`，功能本身已经在。

要达成：

- 说明书写的 `/mcp prepare-uninstall` 去做交接，效果与现有交接相同：条目连同完整配置交回，原本关掉的条目保持关掉。
- 在 `/mcp` 后面写了认不出的话时，告诉正确用法，不要静默列出服务器。
- 不写参数的 `/mcp` 仍是列出服务器。
- 现有的 `/prepare-uninstall` 可以保留，避免已经在用它的人失效。

### 4. 管理页上的密钥不能被别的网页套走

管理页可以显示密钥原文。现在写操作会检查「看起来来自同一地址」；读操作没有这道检查，其中「显示密钥」就是读操作。仅靠「同一地址」也挡不住一种套取：恶意网页把地址指到你的本机，浏览器仍会觉得是同一处。

要达成：

- 浏览器发起的访问，无论读还是写，都要同时满足：来自同一地址，并且地址是本机名或直接写的 IP。
- 不经过浏览器的调用保持原样。
- 如果故意用局域网主机名打开管理页，要有一份单独的允许名单，不在名单里的主机名进不来。
- 允许名单默认是空的。本机和直接写的 IP 不需要加入名单。
- 名单放在插件设置页，和下面第 5 条的开关同一处，不放进安装配置。默认空着即可用；只有要用局域网里的电脑名打开时，才把那个名字加进去。页面本身也走上面的地址检查，没在名单里的电脑名打不开页面，也就不能自己把自己加进去。

### 5. 模型要新加或改一个本地程序时，先问人

对话里的模型现在可以登记一条本地命令。登记时会马上试着启动；之后开机预热，以及每个会话，还可能再启动。没有询问。

要达成：

- 只问「新加了要执行的本地命令」或「改了要执行的本地命令」（要执行的程序、参数、环境、工作目录）。
- 改备注、只改档位、换远程地址、从系统配置导入、在管理页里改，都不问。
- 询问时要让人看到将要执行的程序和参数，以及它之后还会再被启动。
- 这台宿主如果没有询问通道，保持现在的静默放行，不要假装问过，也不要当成拒绝。通道在、但本会话把审批关掉了，该问的时候就问；宿主因此拒绝，就不保存、不启动。
- 人拒绝后，不保存这条新的或改过的本地命令，也不启动它。
- 插件设置页提供三档，默认「跟随当前对话的 DSH 权限」：完全权限直接放行；工作区可写和只读先询问。
- 另两档是「每次都问」和「始终放行」，也在同一设置页。三档都由人在设置页改，不写进安装配置。

### 6. 常用工具不要每说一句话就卸下再挂上

连上之后，连接会留在当前会话里。但每个对话回合仍会把这个常用工具从工具列表里拆掉再挂上。一个连不上的常用工具，每个回合都会再试一次，最长卡住大约 30 秒。

要达成：

- 配置没变、并且这个会话里已经挂好时，这一轮什么也不做。
- 配置刚改过必须马上生效。例如刚关掉其中一个工具，不能因为「已经在跑」就继续留在列表里。人改了命令、参数、环境或工作目录后，清掉失败状态并马上再试一次。
- 这一轮没连上时，不再自动重试，之后每句话也不再干等。档位记录仍是常驻，管理页标明连接失败、当前按按需处理。不自动启动。
- 降级期间，模型要先加载再用，不能直接当已经挂好的常驻工具来调用。管理页刷新快照，或对话里加载，才再试。这一次连上之后，清除失败状态，恢复常驻自动挂载；还是失败就继续降级。
- 只影响常驻这一档。按需不会在每句话之前拆掉再挂上，连不上也不降级。关掉的工具保持现在的行为。

## 顺手，但不是功能

这三件不构成给用户的新功能。若做上面的改动，一并处理。

- 每次改系统配置都会复制一份旧文件，里面可能有密钥，而且一直累积。只留最近 5 份。
- 对外报的版本号现在仍是 `0.1.0`，应改成实际发行版本。
- 部分测试写死了 `D:/Github/...`。在别的系统上会造出假的 `D:` 目录。换掉这些路径。`session-audit` 那一项已经换过。

## 明确不做

- 不把管理页默认改成英文。界面保持中文。
- 不把注入给模型的那段中文用法说明改成英文。
- 不改目录消息的写法。当前写法是为了让旧会话在格式升级后仍打得开，这次不动。
- 不改「按会话各自启动工具」这一已定结构。第 6 条只约束「什么时候重新挂、连不上之后如何降级」。

## 已定选择

2026-09-24 讨论定下。不再待定。

| 事项 | 选择 |
| --- | --- |
| 局域网主机名允许名单 | 插件设置页，默认空。本机名和直接写的 IP 不用填 |
| 模型登记或修改本地程序 | 设置页三档，默认跟随当前对话的 DSH 权限：完全权限放行，工作区可写和只读询问。另两档为每次都问、始终放行 |
| 常驻连接失败 | 不自动重试。仍标记常驻，状态为连接失败并按按需处理；手动加载成功后恢复常驻 |
